# 第 4 课：Agent 主循环

> 预计 60 分钟｜动手文件：`agent.py` + `llm_client.py`｜前置：第 3 课

## 一、目标
把固定的两轮请求泛化成通用循环：工具调用 N 轮都能接住。完成后你能讲清楚"什么是 Agent"。

## 二、理论（10 分钟读完）
**Agent = while 循环 + 停止条件。** 其余都是装饰。

    循环体：发送 → 看响应
        没有 tool_calls（stop）  → 拿到最终答案，返回
        有 tool_calls            → 申请书入历史 → 逐个执行工具 → 结果入历史 → 再发

为什么需要循环：
- 一次问两件事 → 模型一轮申请两个工具
- 工具返回错误 → 模型看到错误消息，自我纠正重试（或正确解释）
- 一个工具的答案是下一个工具的输入 → 连续调用

两个安全阀：
1. **max_steps**：连续 N 轮还在调工具就强制停（防死循环）
2. **try/except**：工具报错时，把【错误消息】喂回给模型——错误成了模型的下一轮输入，这就是循环的魔力（自我修复）

结构约定（为第 5、6 课铺垫）：
- `run_agent(user_text, history)` 返回 `(final_answer, 可复用history)`
- 返回的 history = messages 去掉最前面的 system（每轮开头会重新拼 system，不能重复进历史）

## 四、验收（按顺序跑，每句记下"调了几轮、调了哪些工具"）
- [ ] `17*23+8等于多少？` → 399（1 轮工具调用）
- [ ] `现在几点？` → 调 get_current_time
- [ ] `帮我算 5 的 3 次方，顺便告诉我现在几点` → 同一轮 2 个 tool_calls（125 + 时间）
- [ ] `sqrt(16)等于多少？` → 模型可能自己翻译成 16**0.5（零报错——它读了工具描述并自适应）
- [ ] `17/0等于多少？` → 工具报错 → 模型正确解释"除数不能为 0"（错误喂回的自我修复）
- [ ] `17+*8等于多少？` → 模型可能一轮算出两种解释都给你
- [ ] `17*abc+1等于多少？` → 模型可能不调工具，直接反问要 abc 的值

## 六、常见坑
- "申请书"（含 tool_calls 的 assistant 消息）必须进历史，这是 tool 结果的前置
- 模型可能幻觉出不存在的工具名——查表查不到也是一种错误，把错误消息喂回
- 错误分类越精确（参数错误/未知工具/执行异常），模型自我纠正越准
- run_agent 返回 history 时记得 `messages[1:]`，把 system 摘出去
